# TRACE M3.3 — Adversarial Review

## Review decision

**APPROVED for M3.3 review**, with the limitations listed below.

The adversarial suite goes beyond the original 16 regression fixtures and confirms that TRACE reasons about semantic interactive targets and measured responsive context rather than matching the supplied examples by exact dimensions or names.

No commit or push was performed. The working tree remains uncommitted for review.

## Implementation reviewed

### `server/render-url-core.mjs`

Reviewed and strengthened:

- Semantic interactive ancestor resolution using `closest()` for native controls and supported ARIA roles.
- Center hit-test resolution through the nearest semantic interactive ancestor.
- Preservation of the hit-test selector and tag as supporting evidence.
- Computed padding capture without artificially adding padding to the bounding box.
- Detection of hidden state from display/visibility, tiny clipped geometry, clipping/inset styles, utility naming patterns, and constrained off-screen positioning.
- Rendered control collection from semantic controls rather than arbitrary child SVG/span/icon elements.

### `src/analyzer.ts`

Reviewed and strengthened:

- 44×44 remains a warning signal, not automatic proof of a UX problem.
- Descendant measurements are ignored when an interactive ancestor selector differs from the measured selector.
- Native controls and ARIA button/link/checkbox/menuitem roles are eligible targets.
- Non-interactive spans and divs are not target findings.
- Visually hidden controls are excluded.
- Textual anchors with meaningful horizontal geometry are not treated like tiny icon controls solely because their height is below 44px.
- Missing viewport metadata requires rendered mobile evidence such as overflow or an element extending outside the viewport.
- Existing overflow, accessibility, image, and heading rules remain active.

### `src/types.ts`

Added evidence fields for:

- `role`
- `visuallyHidden`
- `interactiveAncestorSelector`
- `hitTestSelector`
- `hitTestTag`
- `padding`

## Remaining weaknesses

1. The renderer captures computed padding but does not independently model the browser accessibility tree or platform-specific touch hit testing.
2. CSS source-rule acquisition for live URLs remains outside the current architecture; source-rule correlation is strongest for ZIP/GitHub inputs with CSS/SCSS files.
3. A complex custom interactive widget using an unsupported ARIA role may still require future role coverage.
4. Off-screen hidden detection is intentionally conservative and requires a small/clipped/utility-pattern signal to avoid hiding legitimate off-canvas controls that are actually broken.
5. The original M3.2 manual audit files are unavailable locally, so no direct case-by-case before/after audit comparison is claimed.
