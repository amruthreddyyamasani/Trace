# TRACE M3.3 — Ground-Truth Accuracy Tuning Validation

## Scope

This milestone tunes the two weak rules identified by the supplied M3.2 owner-audit conclusions:

1. Mobile target-size findings based only on a bounding-box threshold.
2. Missing viewport metadata treated as a meaningful responsive problem without rendered context.

The original M3.2 audit files are **not present in this repository**. The conclusions below were supplied as authoritative handoff input; this implementation does not claim to have rerun the original 30 cases.

## Ground truth used

The supplied purposive audit contained 30 findings:

| Label | Count |
|---|---:|
| True positive | 8 |
| False positive | 6 |
| Technically true / low practical importance | 16 |
| Duplicate | 0 |
| Uncertain | 0 |

Descriptive metrics from that audit were 57.1% binary precision (8 / 14 TP-or-FP cases), 26.7% actionable true-positive share (8 / 30), and 80.0% technically valid including low-practical-importance findings (24 / 30). Recall was not measured. These numbers are not treated as representative accuracy estimates for TRACE.

The dominant failure was the target-size rule: 20 of 30 audited findings were small-target cases, with 1 true positive, 3 false positives, and 16 technically true / low-practical-importance cases. The supplied examples show why a small descendant SVG, a visually hidden skip link, or a wide text link must not automatically become a product finding.

## Rule changes

### Interactive ancestor resolution

`server/render-url-core.mjs` now resolves the nearest semantic interactive ancestor using `closest()` for buttons, anchors, form controls, supported ARIA roles, and menu items. Rendered control measurements are collected from semantic controls rather than from arbitrary descendants. Each measured element can retain:

- `interactiveAncestorSelector`
- `hitTestSelector`
- `hitTestTag`
- computed padding
- `visuallyHidden`

The center hit-test is retained as supporting evidence and resolves through the same interactive ancestor list when it lands on a child SVG, span, icon, or wrapper.

### Actual target geometry

The analyzer still uses 44×44 CSS pixels as a warning signal, but it is no longer automatic proof of a UX problem. A target candidate must be visible, semantic or linked to a semantic ancestor, and below the threshold in both dimensions. The analyzer excludes descendant artifacts, including SVG/span/i/div measurements that identify an interactive ancestor, and wide text links whose actual anchor bounds provide a meaningful horizontal target.

The finding evidence now names the actual semantic tag and selector, reports the measured dimensions, includes the hit-test resolution, and records computed padding when available. No dimensions are inflated to avoid a finding.

### Hidden-control handling

The renderer identifies evidence-supported visually hidden patterns using visibility/display state, tiny clipped geometry, clipping/inset styles, and common accessibility utility naming patterns. Visually hidden controls are excluded from target-size findings. This is pattern-based rather than a text special case for “Skip to content.”

### Target-size contextualization

The following generalized behaviors are covered:

- An actual 18×18 button remains detectable.
- A 30×30 SVG inside a 48×48 button does not create a false finding.
- A 30×30 span inside a larger interactive parent is resolved to that parent.
- Wide text links are not treated as actionable target failures solely because height is below 44px.
- 1×1/clipped accessibility controls are excluded.
- Actual 38×35 and 32×32 buttons are evaluated as buttons.
- A wide button is not classified solely from its height.

### Viewport contextualization

Missing viewport metadata is no longer reported in isolation. It becomes a responsive finding only when rendered mobile evidence also shows a measurable symptom, such as document overflow or an element extending beyond the mobile viewport. A healthy rendered page without viewport metadata therefore does not receive a strong viewport finding from metadata alone.

Existing source and rendered checks for accessible names, missing image alt text, genuine mobile image overflow, and heading/layout constraints remain active.

Stripe was not used in this comparison because its renderer blocked the automated browser session in the earlier validation run.

## Limitations

- The original 30-case M3.2 audit and its evidence are not present in this repository.
- This implementation was tuned from the supplied audit conclusions, not by rerunning that audit.
- No recall was measured.
- No statistically representative accuracy claim is made.
- Real-site results are regression checks, not human ground truth.
- The current renderer captures computed padding and ancestor/hit-test selectors, but it does not perform a full browser accessibility-tree audit.
- Source CSS acquisition for live URLs remains outside the existing architecture; source-rule correlation is strongest for ZIP/GitHub inputs that contain CSS/SCSS files.
