# TRACE anti-AI sweep

Run this before calling a build “done”. It is intentionally opinionated.

## Copy

- Does every sentence describe a real product behavior?
- Are there any generic phrases such as “seamless”, “next-generation”, “unlock”, “revolutionize”, or “elevate” that do not add information?
- Are all metrics, claims, and badges backed by real data?

## Layout

- Is there a real hierarchy, or are several sections styled as identical cards?
- Can any decorative container be removed without losing information?
- Are border radii, shadows, and gradients used because they serve a function or simply because they are conventional AI UI patterns?

## Motion

- Does motion explain state, continuity, cause/effect, or spatial relationships?
- Does the page remain strong with motion disabled?
- Are there any simultaneous entrances that create visual noise?

## Product identity

- Can someone describe why TRACE looks like TRACE rather than “another dark AI SaaS”?
- Are there custom details that come from the product concept itself?
- Does the interface language match the word “autopsy”, “trace”, and evidence-led diagnosis?

## UX

- Is the first useful action obvious without being oversized?
- Does each screen reveal new information rather than restating marketing copy?
- Are empty, loading, error, partial, and completed states honest?

## Technical

- Check keyboard navigation.
- Check mobile width at 320px, 375px, and 430px.
- Check reduced-motion behavior.
- Check console errors and failed network requests.
- Check that no placeholder or demo finding is presented as real analysis.
